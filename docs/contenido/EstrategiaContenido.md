# Estrategia de Contenido Inicial (Seeding) — Appfasia
> **Documento vivo** · Versión 0.1

---

## 1. Resumen Ejecutivo

El prototipo requiere un catálogo mínimo de **~300 recursos de palabras** distribuidos en 5 niveles y 12 categorías semánticas. Cada recurso necesita: texto, imagen (PNG/SVG) e audio (MP3). La estrategia prioriza herramientas gratuitas y automatización para reducir el trabajo manual.

## 4. Estrategia de Imágenes

### Fuentes por nivel

| Niveles | Fuente | Estilo | Justificación |
|---|---|---|---|
| **1 y 2** | **Flaticon** (Free tier) | Flat / Cartoon colorido | Simplicidad visual, alta legibilidad para niños 0-4 años |
| **3 y 4** | **Freepik** (Free tier) | Ilustración detallada | Mayor complejidad visual acorde al nivel cognitivo |
| **5** | **Freepik** (Free tier) | Ilustración realista / conceptual | Conceptos abstractos requieren representación más elaborada |

### Criterios de selección de imágenes

- **Fondo blanco o transparente** — sin distractores visuales
- **Estilo consistente dentro del mismo nivel** — misma paleta y trazo
- **Resolución mínima:** 512×512px (se sirve como WebP desde Azure Blob)
- **Licencia:** Solo imágenes con licencia Flaticon Free / Freepik Free para uso comercial

### Nomenclatura de archivos

```
recursos/imagenes/{nivel}/{categoria}/{id_recurso}.webp

Ejemplos:
  recursos/imagenes/nivel1/animales/W_001.webp   → Perro
  recursos/imagenes/nivel2/ropa/W_095.webp       → Abrigo
  recursos/imagenes/nivel5/abstracto/W_280.webp  → Justicia
```

## 5. Estrategia de Audios (Azure TTS)

### Voces seleccionadas

| Voz | Código Azure | Uso | Justificación |
|---|---|---|---|
| **Dalia** | `es-MX-DaliaNeural` | Palabras de recursos (estímulos) | Voz femenina cálida, pronunciación clara del español mexicano |
| **Jorge** | `es-MX-JorgeNeural` | Instrucciones del sistema | Voz masculina amigable, variedad de voz en la experiencia |
| **Beatriz** | `es-MX-BeatrizNeural` | Feedback del avatar | Voz más joven y expresiva para el personaje del avatar |

> **Costo:** Azure F0 incluye 500,000 caracteres/mes de TTS Neural. Con 315 palabras de ~8 caracteres promedio = **~2,520 caracteres** para las palabras. Las instrucciones y feedback suman ~50,000 caracteres estimados. Muy dentro del tier gratuito.

### Tipos de audios a generar

```
recursos/audios/
├── palabras/          → una pronunciación clara de cada palabra
│   └── {id_recurso}.mp3         (voz: Dalia)
├── instrucciones/     → prompts de los ejercicios ("Toca el animal que hace muuu")
│   └── INSTR_{codigo}.mp3       (voz: Jorge)
└── feedback/          → respuestas del avatar ("¡Muy bien!", "¡Casi!", "¡Inténtalo!")
    └── FB_{codigo}.mp3          (voz: Beatriz)
```

### Script de generación en Python (Azure TTS)

```python
import azure.cognitiveservices.speech as speechsdk

def generate_audio(texto: str, voz: str, output_path: str):
    config = speechsdk.SpeechConfig(
        subscription=AZURE_SPEECH_KEY,
        region=AZURE_REGION
    )
    config.speech_synthesis_voice_name = voz
    config.set_speech_synthesis_output_format(
        speechsdk.SpeechSynthesisOutputFormat.Audio16Khz32KBitRateMonoMp3
    )
    synthesizer = speechsdk.SpeechSynthesizer(
        speech_config=config,
        audio_config=speechsdk.audio.AudioOutputConfig(filename=output_path)
    )
    synthesizer.speak_text_sync(texto)

# Ejemplo de uso batch
palabras = [("W_001", "Perro", "es-MX-DaliaNeural"), ...]
for id_rec, texto, voz in palabras:
    generate_audio(texto, voz, f"recursos/audios/palabras/{id_rec}.mp3")
```

## 6. Estructura del Archivo de Seeding (CSV maestro)

El equipo de contenido trabajará sobre un CSV que alimentará el script de importación. Una fila = un recurso.

```csv
id_recurso,tipo,texto,nivel_sugerido,fonema_objetivo,id_categoria,categoria_nombre,dificultad_art,imagen_archivo,audio_archivo,tags
W_001,palabra,Perro,1,rr,CAT_001,animales,alta,perro.webp,W_001.mp3,"domestico|fonema_vibrante"
W_002,palabra,Gato,1,t,CAT_001,animales,baja,gato.webp,W_002.mp3,"domestico|mascotas"
W_003,palabra,Vaca,1,v,CAT_001,animales,baja,vaca.webp,W_003.mp3,"granja|onomatopeya_muu"
W_095,palabra,Abrigo,2,gr,CAT_003,ropa,media,abrigo.webp,W_095.mp3,"invierno|sinfon_br"
W_280,palabra,Justicia,5,s,CAT_012,abstracto,baja,justicia.webp,W_280.mp3,"valores|nivel_superior"
```

**Columnas del CSV:**

| Columna | Tipo | Descripción |
|---|---|---|
| `id_recurso` | `VARCHAR(10)` | ID único (ej. W_001) — generado secuencialmente |
| `tipo` | `VARCHAR(20)` | `palabra`, `frase`, `metáfora` |
| `texto` | `TEXT` | La palabra o frase en español |
| `nivel_sugerido` | `INT (1-5)` | Nivel de competencia del plan |
| `fonema_objetivo` | `VARCHAR(10)` | Fonema principal a evaluar (ej. `rr`, `bl`, `tr`) |
| `id_categoria` | `VARCHAR(10)` | ID de categoría semántica |
| `categoria_nombre` | `TEXT` | Nombre legible de la categoría |
| `dificultad_art` | `VARCHAR(10)` | `alta`, `media`, `baja` (dificultad articulatoria) |
| `imagen_archivo` | `VARCHAR(100)` | Nombre del archivo de imagen local (ej. `perro.webp`) — el script lo sube a Azure Blob y registra la URL CDN |
| `audio_archivo` | `VARCHAR(100)` | Nombre del archivo MP3 generado por Azure TTS (ej. `W_001.mp3`) — se sube al mismo Blob container |
| `tags` | `TEXT` | Lista separada por `\|` para búsqueda con GIN |

## 7. Pipeline de Importación

Una vez completado el CSV y generados los assets, el script de importación:

```
seed_content.py
    │
    ├─► Lee seed_resources.csv
    │
    ├─► Para cada recurso:
    │     ├─► Genera audio (Azure TTS) → resources/audios/palabras/W_XXX.mp3
    │     ├─► Sube imagen a Azure Blob Storage → registra URL CDN
    │     ├─► Sube audio a Azure Blob Storage → registra URL CDN
    │     └─► Inserta fila en PostgreSQL tabla `recursos` con URLs del CDN
    │
    └─► Genera reporte: X recursos importados, Y errores
```

```
scripts/
├── seed_content.py          # Script principal de importación
├── generate_audios.py       # Batch TTS con Azure
├── upload_assets.py         # Subida masiva a Azure Blob Storage
└── seed_resources.csv       # El catálogo maestro (editado manualmente)
```

## 8. Criterios de Calidad por Recurso

Antes de marcar un recurso como listo para producción, debe cumplir:

| Criterio | Verificación |
|---|---|
| Imagen existe en Blob Storage | URL devuelve HTTP 200 |
| Audio existe en Blob Storage | URL devuelve HTTP 200 |
| Duración del audio | Entre 0.3s y 3s para palabras simples |
| `fonema_objetivo` completado | No puede estar vacío |
| `nivel_sugerido` coherente | Revisión manual por nivel |
| Sin duplicados de texto | Query `SELECT COUNT(*) WHERE texto = X` = 0 antes de insertar |
| Imagen sin texto visible | Revisión visual (para no mezclar modalidades en ejercicios T-S) |

## 9. Fases de Carga del Contenido

Para el prototipo, el contenido no tiene que estar completo desde el día 1. Se propone cargarlo por fases:

| Fase | Contenido | Cuándo |
|---|---|---|
| **Fase 0 (MVP)** | Nivel 1 completo (55 palabras) + 20 de Nivel 2 | Antes de primera demo |
| **Fase 1** | Niveles 1 y 2 completos (120 palabras) | Sprint 2 |
| **Fase 2** | Niveles 1, 2 y 3 completos (195 palabras) | Sprint 3 |
| **Fase 3** | Catálogo completo (315 palabras) | Prototipo final |

> **Regla práctica:** El motor de inferencia necesita mínimo **15 palabras por categoría activa por nivel** para que la Regla de No Repetición funcione dentro de una sesión completa.
